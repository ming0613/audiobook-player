# 有声书 App · MVP 产品需求文档 (PRD v0.1)

> 状态：已确认 · 用户故事已迁入 GitHub Issues
> 日期：2026-09-22
> 产品定位：一个有意思的**离线**有声书 App（本地音频文件，无服务器依赖）

---

## 1. 愿景 (Vision)

为本地有声书收藏者打造一个纯粹的离线收听工具：把音频文件夹变成一个有进度记忆的书架，随时随地接着上次听。

参考蓝本：[Voice](https://github.com/PaulWoitaschek/Voice)（Kotlin + Jetpack Compose），我们借鉴其架构，但保持自己的设计与迭代节奏。

## 2. 核心概念模型

| 概念 | 定义 | 备注 |
|---|---|---|
| 书 (Book) | 用户设备上的**一个文件夹** = 一本书 | MVP 阶段 |
| 章节 (Chapter) | 文件夹内的**一个音频文件** = 一章 | 按文件名自然排序 |
| 书架 (Library) | 用户指定的一个或多个"书库根目录"下所有书的集合 | |
| 进度 (Progress) | 每本书独立记录：当前章节 + 章内位置 + 上次收听时间 | 核心需求 |
| 封面 | MVP 不做，后续迭代从文件夹图片/内嵌封面读取 | 已确认延后 |

## 3. MVP 用户故事 (Sprint 1)

### Epic A · 书架与书籍管理
- **US-A1** 作为用户，我希望指定一个本地文件夹作为书库根目录，以便 App 能发现我所有的有声书。
- **US-A2** 作为用户，我希望在书架页看到所有书（书名 = 文件夹名），以便快速选择。
- **US-A3** 作为用户，我希望每本书在书架上显示**完成百分比**，以便一眼看到听到哪了。

### Epic B · 播放
- **US-B1** 作为用户，我希望点开一本书就能从**上次的位置**继续播放，以便无缝续听。
- **US-B2** 作为用户，我希望有播放/暂停、进度条拖动、上一章/下一章按钮，以便控制收听。
- **US-B3** 作为用户，我希望调节**倍速**（如 0.75x / 1.0x / 1.25x / 1.5x / 2.0x），以便按自己的节奏收听。

### Epic C · 进度持久化
- **US-C1** 作为用户，我希望每本书记住：当前章节、章内播放位置、上次收听时间，以便在多本书之间自由切换不丢失进度。
- **US-C2** 作为用户，我希望书架按"最近收听"排序，以便快速回到正在听的书。

### 明确不做（MVP 范围外，记入 Backlog）
- 书籍封面、书签、睡眠定时、在线音频源、播放列表自定义、账号/云同步

## 4. 验收标准示例（以 US-C1 为例）

- 播放过程中退出 App（杀进程），重新打开该书 → 从退出的章节和位置继续
- 书 A 听到一半切到书 B，再切回书 A → A 的进度保持不变
- 书架页每本书显示百分比 = 已听时长 / 全书总时长（误差 < 1%）

## 5. 技术草案（Sprint 1 技术选型）

- **语言/UI**：Kotlin + Jetpack Compose（Material 3）
- **播放引擎**：Media3 / ExoPlayer（Google 官方，支持倍速、后台播放、通知栏控制）
- **本地数据库**：Room（存书籍、章节、进度）
- **架构**：MVVM + Repository 模式（单 Activity + Compose Navigation）
- **最低系统**：Android 8.0 (API 26)，覆盖约 95% 设备
- **构建**：Gradle (Kotlin DSL)，APK 直接安装到手机

## 6. Sprint 1 目标（2 周）

> 交付一个能装进手机、能真实听书的"丑但能用"版本：
> 选书库 → 书架列表 → 点书播放（含续听）→ 倍速 → 进度记住。

UI 精致度不做要求，先把骨架和数据流跑通；视觉迭代从 Sprint 2 开始（届时引入 Axure 原型）。
